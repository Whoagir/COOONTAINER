# Чеклист оценки исполнения

Оцениваешь **текущую сборку**, не мечту. ТЗ: `DESIGN_TZ.md`.  
Не смотри в код, пока не сыграл. Код соврёт «фича есть». Руки скажут, смешно ли.

**Оценки**

| Балл | Значение |
|------|----------|
| 0 | Нет, сломано, или есть и убивает кайф |
| 1 | Работает, но сухо / неочевидно / без прикола |
| 2 | Как в ТЗ: уже клип, уже ор |

Пиши балл и **одно предложение почему**. В конце сложи. Максимум **100**.

| Сумма | Вердикт |
|-------|---------|
| 0–40 | Каркас, не игра |
| 41–70 | Системы есть, кайф дырявый |
| 71–85 | Почти продукт, дыры точечные |
| 86–100 | Можно звать кореша без извинений |

Два захода: **соло 40–60 мин**, потом **кооп 2 человека 30+ мин**. Баллы коопа — отдельно, в конце листа.

## Как пользоваться

1. Распечатал или открыл рядом. Играешь, не ставишь паузу на каждый пункт.  
2. После блока — сразу баллы, пока помнишь.  
3. Кооп не подменяй «ну в соло же работает».  
4. Расхождение с ТЗ (например сутки/день-ночь) оценивай так: **ломает кайф?** Если да — 0. Если прикол и ты его принял — 2 и забудь ТЗ в этом пункте.

Лист для повторных сборок: дата / сумма соло / сумма кооп / клип.
